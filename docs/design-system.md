# 设计系统与第一轮收敛

这一轮不是「再改几个页面」，而是先承认问题：**App 没有统一的设计语言**。
量化结果（改造前，扫 `ios/Awake/*.swift`）：

| 指标 | 改造前 | 现在 |
| --- | --- | --- |
| 写死字号 | 17 种取值、44 处 `.font(.system(size:))` | 剩 7 处（封面/图标按尺寸算的表达式），其余全部改为语义字号 |
| 圆角取值 | 11 种 | 三档（8 / 12 / 16） |
| 间距取值 | 20 种 | 4 的倍数（4 / 8 / 12 / 16 / 24 / 32） |
| `caption` 说明小字 | 164 段 | 120 段（34 段长文改为折叠说明） |
| 长句字面量（>30 字） | 101 条 | 58 条 |
| <44pt 的点击目标 | 12 个 | 11 个（剩余为装饰性图形） |

## 设计语言（`ios/Awake/DesignSystem.swift`）

- **间距**：`DS.Space`，4 的倍数；页面左右 20、区块 24、行内 12。
- **圆角**：`DS.Radius` 三档，8（小控件）/ 12（行与卡）/ 16（大面板）。
- **动效**：`DS.Motion` 只有 0.18 / 0.26 两档；减弱动效时传 nil。
- **结构线**：0.5pt 的 `DS.hairline`，不用阴影分层。
- **点击目标**：`DS.hit = 44`，所有可点行/按钮的最小高度。
- **组件**（全 App 复用，不再各页自己拼）：
  - `AwakeSectionTitle`：小号宽字距标题 + 右侧状态；
  - `AwakeRow`：图标 + 标题 + 一句说明 + 状态/箭头（设置、添加音乐、首页共用）；
  - `AwakeNote`：**默认折叠**的说明，点开才展开——长解释不再铺在页面上；
  - `AwakeCard` / `AwakeEmptyState` / `AwakePrimaryButton` / `AwakeSecondaryButton`。

## 页面收敛

- **首页（为你）**：删掉与底部 tab 重复的四个入口（听感反馈、听书已经在别处有入口），
  只留「听歌搭子 / 本周总结」两个没有别处入口的工具；推荐列表加结构线、只算一次排序；
  空态只给一个主行动「去添加音乐」。
- **曲库**：来源筛选从下拉菜单改成一排 chip（一次点击、看得到每个来源的曲数）；
  空态从三条并列按钮收成一个主行动；搜索与工具栏不动。
- **设置**：顶部状态摘要卡（版本、曲目/歌单/来源/缓存、AI 是否配置）；
  入口统一 `AwakeRow`；来源的刷新/移除收进 44pt 菜单；两个维护分区合并；
  六段长说明改 `AwakeNote`。
- **添加音乐**：三种服务器各一行并写清要求，点哪行带类型进编辑器；
  说明改折叠；已连接与最近一次导入各自成区。
- **播放页**（上一轮）：环境光、跟随歌词、折叠仪器区，同样遵守这套间距与字号。
- **评测 / 声音 / 书库 / 设备 / 播放列表导入 / 插件 / 曲目曲线**：长说明批量改为
  `AwakeNote`（共 34 段），页面骨架未动。

## 没做完的（下一轮的真名单）

- **`Panel` / `AwakeCard` 两套并存**：老页面仍用 `Panel`，还没全量换成 `AwakeCard`。
- **字号未全量收口**：`EquipmentViews`、`BooksView`、`PlaylistImportView`、`PluginStore`
  里仍有 `.font(.system(size:))` 直接写死；这一轮只统一了外壳与行/卡/说明。
- **<44pt 的目标还有 11 处**，其中多数是封面/图形，需要逐个确认是否可点。
- **深色之外的皮肤**：这一轮截图只用深色；玻璃/白皮肤的对比度与层次未逐页检查。
- **真机手感**：所有截图来自模拟器，滚动、点击、返回手势没有手点过；
  XCTest 仍无法在本机执行（没有 `Simulator.app`）。

## 顶部品牌与翻页规则（本轮新增）

- **桌面**：删掉侧栏顶部那个只用来展示的 `awake.` 字样（它不可点、不显示状态，只占一条拖拽区）。
  页面身份由顶栏面包屑（「你的聆听空间 / 当前页」）回答；窗口拖拽仍由顶栏承担。
  新增 `⌘1–⌘6` 直接切侧栏分区，顺序与侧栏一致。
- **iOS**：设置页摘要卡不再以品牌名开头，改成「本机曲库 + 版本」，下面才是真实数字。
- **iOS 横滑换 tab**：规则抽成 `TabPaging`（纯函数）并由 harness 断言：
  - 向左滑 = 下一个 tab，向右滑 = 上一个，**到头不循环**；
  - 水平位移 ≥80pt 且 ≥ 竖直位移的 2 倍才算横滑；
  - 起手点在屏幕左右 24pt 内不翻（留给系统返回手势）；
  - 起手点在横向控件（来源 chip、EQ 曲线、滑杆）内不翻——这些区域用 `.tabSwipeExempt()` 上报；
  - 翻页带 selection 触感。
- 已知边界：iOS 原生 `TabView` 没有「整页跟手」的分页动画，翻页是切换 + 淡入，
  不是手指拖动过程中的实时位移。要跟手分页得换掉原生 tab bar（同时失去 iOS 26 的浮动
  tab bar 与 mini player 附件），这一轮没有做。

## 决定：不做「跟手分页」

2026-11-24，用户确认：**保持现有规则**（横滑触发切换 + 淡入），不为了跟手分页换掉原生 tab bar。
因此不会失去 iOS 26 的浮动 tab bar 与 mini player 附件。
如果以后要做，代价写在上面「已知边界」里，需要单独立项。

## 第二轮字号收口（2026-11-24 晚）

- 把 `ios/Awake/*.swift` 里 44 行写死的 `.font(.system(size: N))` 机械映射成语义字号：
  9–11 → `.caption2`，12 → `.caption`，13 → `.footnote`，14–15 → `.subheadline`，16–17 → `.body`，
  18–19 → `.title3`，20–22 → `.title2`；等宽写法改为 `.monospaced()`。
- 剩下 7 处是封面占位、图标大小这类按尺寸计算的表达式，属于合理用法。
- 声音页与评测页截图复核：预设卡、滑杆、耳机卡、说明折叠都没有因字号变化错位。

# Awake 接力协议（v2，双向）

目标：把正在播放的曲目与进度交给同一局域网内的另一台 Awake 继续播放。两个方向共用一套载荷、配对码与匹配规则：**手机 → 电脑**（v1，已发布）与 **电脑 → 手机**（v2 新增）。不走云端、不发送音频、不保存用户凭据。

## 方向与角色

| 方向 | 接收端 | 发送端 | mDNS TXT 标记 |
| --- | --- | --- | --- |
| 手机 → 电脑 | 桌面 App | iOS App「接力到电脑」 | 接收端 `to=desktop`（旧版无该键，按 desktop 处理） |
| 电脑 → 手机 | iOS App「接收接力」 | 桌面 App「接力到手机」 | 接收端 `to=phone` |

两端都浏览同一个服务类型 `_awake._tcp`，靠 TXT 里的 `to` 区分对方是电脑还是手机：手机发送者不会把另一台手机当成电脑，电脑发送者只列手机。

## 接收端（电脑或手机，规则相同）

- 用户点「接收接力」/「开始接收接力」后启动：
  - HTTP 服务监听全部网卡的临时端口，只接受局域网请求；
  - 通过 mDNS 发布 `_awake._tcp.local.`，TXT 含 `v=2`、`name=<设备名>`、`code_required=1`、`to=desktop|phone`；
  - 生成 6 位数字配对码显示在界面上；10 分钟没有请求自动过期；停止接收即失效。
- 每个接受到的请求：每 2 秒最多 1 个（含错码请求，避免暴力猜），配对码错 5 次即换新码并返回 429；请求体上限 8 KB；超过 10 秒没读完即断开。
- 只接受 `POST /handoff`；其他方法或路径 404；`Content-Type` 必须是 `application/json`，否则 400。
- 请求体：

```json
{
  "code": "123456",
  "track": { "title": "曲名", "artist": "艺人", "album": "专辑", "duration": 225.0 },
  "position": 42.5,
  "playing": true
}
```

- 响应：
  - 200 `{"ok":true,"matched":true,"title":"...","message":"已开始播放"}`
  - 200 `{"ok":false,"matched":false,"error":"曲库里没有找到这首歌"}`（未匹配）
  - 401 配对码错误；429 尝试过多；400 请求格式错误。
- 匹配规则（两端一致）：曲名 / 艺人 / 专辑归一化（大小写、括号、feat、标点、常见噪声词）后取字符 bigram Dice 相似度；权重曲名 0.55、艺人 0.35、专辑 0.10（缺项按剩余权重归一），再加时长接近度；时长差超过 ±5 秒直接淘汰；阈值 ≥0.62；只在**本地文件存在**的曲目里取最高分。
- 匹配成功后：用接收端当前音量 / EQ 播放该曲目并 seek 到 position；电脑端另向前端 emit `handoff://received` 事件（payload: title, position, matched）。
- 失败信息不包含路径、账号或网络细节。

## 发送端

- 手机端入口：正在播放页「接力到电脑」。仅当有当前曲目时可用。
- 电脑端入口：底部播放条的「数据与接力」→「接力到手机」。仅当有当前曲目时可用。
- 发现：浏览 `_awake._tcp` 并按 `to` 过滤，列出设备名；解析 host/port；展示配对码输入框；提供「手动输入 IP:端口」兜底。
- 发送：`POST http://<host>:<port>/handoff`，JSON 如上，超时 5 秒；成功后提示「已接力到 <设备>」，失败给出可读原因（配对码错误 / 未找到歌曲 / 网络）。
- 不保存配对码；不发送音频文件、账号或 token。

## iOS 侧约束

- `NSBonjourServices` 包含 `_awake._tcp`；`NSLocalNetworkUsageDescription` 说明接力用途（已存在）。
- 手机作为接收端时，只要 App 退到后台、锁屏超时或用户停止，监听与 mDNS 广播立即结束；手机不提供后台常驻接收。

## 安全边界

- 仅局域网；配对码是唯一授权凭据；不提供公网监听、不做端口转发。
- 请求体只含曲目元数据与进度；不含文件路径、凭据、设备标识。
- 用户可随时停止接收；停止后端口关闭、mDNS 注销。

## 兼容性

- v1（只有手机 → 电脑）与 v2 载荷完全兼容：`to` 缺失按 `desktop` 处理，字段未变。
- 桌面 0.9 与 iOS 0.9 同时升级后，双向接力都可用；只升级一端时，另一端仍可正常使用原有方向。

# 播放界面交互复盘与规划

状态：复盘稿。范围是「正在播放」这条线，不含曲库/来源管理（那是另一份）。
目的：先看清现在有几套交互、各自解决什么，再决定内置几种，而不是继续叠加模式。

## 一、现在两端各有什么

| 面 | iOS | 桌面 | 说明 |
| --- | --- | --- | --- |
| 沉浸播放页 | `Views.swift` 全屏 cover | `StageInstrument.vue` | 封面、进度、播放控制、链路条、曲线入口 |
| 迷你条 | `Views.swift` MiniPlayer（tabViewBottomAccessory） | 侧栏 device-card | 回到播放页 / 播放暂停 |
| 刷音乐手势 | `SwipePlayer.swift`：vertical + cards 两模式 | `SwipeMode.vue`：vertical + cards | 上下换歌；卡片左右收藏/跳过 |
| 仪器面板 | `PlayerInstrument.swift` | `StageInstrument.vue` | 31 段曲线、路由数值、静默封面 |
| 队列 | **没有独立队列页** | `queueOpen` + `.queue-panel` | 队列只能整条 play，不能看/改 |
| 歌词 | 只存字段，媒体信息里能看到文本 | 同左 | 播放级没有歌词界面 |
| 有声书播放 | `BooksView.swift` 独立一套 | 同左 | 章节队列、书签 |

结论：两端各有 **6 个播放面**，真正的「交互模式」只有 2 个（vertical / cards），其余是界面状态。

## 二、现在的四个具体问题

1. **两套手势是两份实现，语义还对不上**：`SwipePlayer.swift` 与 `SwipeMode.vue` 里 vertical 与 cards 各写一遍翻页/抽卡逻辑；cards 的右滑=收藏、左滑=跳过，vertical 只有上下换歌——同一根手指在两种皮肤下含义不同，学习成本翻倍。
2. **队列看不见、改不了**：iOS 完全没有队列界面，`player.play(queue)` 之后只能顺序听；桌面有队列面板但不能拖拽排序（另有一条已在发行说明里写明「后端没有不打断播放的重排命令」）。
3. **歌词停在数据层**：`Song.lyrics` 有内容、媒体信息页能看文本，但播放页没有滚动歌词——这是「播放界面」最常被期待的一块。
4. **好东西藏在二级页**：刷音乐要从播放页再进一层；按住旁路 EQ 这种「一边听一边比」的原语目前只有桌面有（`bypassKey.ts`），iOS 没有。

## 三、应该内置几种：2 种皮肤 + 1 套语义 + 4 个状态

不建议再加第三种「模式」。建议收敛成：

| 层 | 内置的东西 | 为什么 |
| --- | --- | --- |
| 语义层（唯一） | 上滑=下一首、下滑=上一首、右滑=收藏、左滑=跳过、按住封面=旁路 EQ | 一根手指一套含义，两端共用同一份状态机与单测 |
| 皮肤层（2 种） | 海报（vertical 翻页）/ 卡片（抽卡） | 皮肤只改视觉与转场，不改语义 |
| 状态层（4 个） | 播放页 / 歌词 / 队列 / 迷你条 | 都是「播放中」的不同切面，不是并列模式 |

也就是说：**内置 2 种视觉皮肤、1 套手势语义、4 个界面状态**。超出这个范围的（例如手势自定义、皮肤编辑器）放进「实验」而不是默认内置。

## 四、可验证的创新点（按能不能验收排序）

- **按住封面旁路 EQ**：与桌面 `B` 键同语义，松手写回原曲线；验收=链路条出现「旁路直通」+ 曲线压平 + 松手恢复。成本低、体感强。
- **手势触觉分级**：下一首/上一首=轻，跳过=中等，收藏=成功提示；验收=真机手感（只能人判断，写进 DoD）。
- **队列抽屉可排序**：iOS 先做「下一首插播 + 删除」，拖拽排序依赖后端「不打断播放重排队列」的能力（桌面已标为未闭合），iOS 侧可先只做本机队列。
- **歌词**：逐行高亮 + 点击跳转位置；验收=有时间戳的歌词文件能跟着走。
- 实验（不进默认）：歌词与曲线联动、播放页手势自定义、皮肤编辑器。

每条都要能在真机上点出来，别用「编译通过」当验收——这是前面几轮反复踩过的坑。

## 六、不做的事（写清楚，免得以后当成遗漏）

- 不做第三种手势模式（例如「摇一摇换歌」）；要加必须替换掉一种皮肤。
- 不做服务端队列重排（桌面已注明后端缺命令）；iOS 只做本机队列。
- 不做歌词在线抓取（当前没有合法来源），只渲染本地已有的时间戳歌词。

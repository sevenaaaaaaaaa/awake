# Telegram 个人媒体库 · 桌面 0.6.1 / iOS 0.7.4

本轮将本地、NAS/WebDAV、Plex 和用户自有 Telegram 音频收藏统一作为个人媒体库入口。新增能力属于软件接入与播放，不提供公共音乐目录、源推荐或解析脚本执行。

## 实现

- 自托管 Python 连接器使用 Telethon 1.45.0 的 Telegram 用户 API。登录仅在用户设备的终端完成；会话和访问令牌以受限文件权限存储。播放器只接收连接器地址及访问令牌。
- 用户选择收藏夹、指定频道，或将聊天文件夹展开成显式频道列表。最多 20 个来源，每个读取最近 100–2000 条消息。文件夹新增频道不会自动扩大读取权限。
- 连接器按已创建的媒体库范围校验文件访问，重新读取消息并检查内容保护与可访问性。HTTP Range 支持跳转，缓冲有界，不在连接器缓存整首音频。请求只读 Telegram 内容，展示回执除外。
- 桌面复用流式解码、后端队列、EQ、系统钥匙串和 15 分钟自动刷新。刷新失败保留旧曲库。
- iOS 复用远程音频下载、可解码验证、本地缓存及原生 EQ。设置新增一次性音频目录导入，跳过符号链接及非音频文件。来源刷新仍为手动操作。
- 两端配置导入支持 JSON/XML/TXT、版本与字段验证、64 KB 上限；导入只填表，密钥必须另填，不执行配置中的代码。
- 保留可用的 Telegram 原始消息链接。桌面曲目列表点击“原始消息”，iOS 长按曲目选择查看。
- 提供文字赞助消息呈现和可见后回执；当前拒绝无法完整呈现的照片/媒体赞助内容。该部分仍需要真实频道和 Telegram 条款审查，不声明已获得官方客户端认证。
- Telegram 曲目的元数据和自动提取的偏好标签不发给云端 AI；本地推荐保留。此边界由后端与 iOS 候选过滤实现。

## 验证边界

本轮自动测试使用自生成 WAV、稀疏两小时 WAV、回环 HTTP 服务及显式标记的 Telegram 协议夹具。验证实际的 HTTP 鉴权、创建媒体库、目录读取、字节范围传输、解码、跳转、下载与配置校验。UI 夹具不属于真实 Telegram 频道，未向 Telegram 发送登录或读取请求。

完整结果与日志摘要见 [validation-telegram.log](validation-telegram.log)。未使用真实 Telegram 账号、NAS、付费音乐源或外部 AI 服务。没有完成 App Store 审核、完整 Telegram 客户端条款适用性认证或真实耳机听感测量。

## 安装与使用

- 桌面：`dist-rust/Awake.app`（macOS 14+，本机构建并 ad-hoc 签名）。
- iOS：`dist-ios/Awake-0.7.4-ios-arm64-unsigned.ipa`（iOS 17+，需重签）。
- 连接器：[部署说明与个人配置示例](../Tools/telegram_connector/README.md)。

连接器必须保持运行；iPhone 不能使用电脑的 `127.0.0.1` 地址。外部连接使用 HTTPS，局域网 HTTP 仅用于用户受信任的网络。个人会话目录不能随源码或配置分享。

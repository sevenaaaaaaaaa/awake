# 能力深度盘点与产品规划（v1）

> 目标不是再加功能，而是把「耳朵唤醒 / 每首歌的 EQ / agent 自动调」这三句话说成立。
> 现状：代码量不小（iOS 15.6k 行 / Rust 22.3k 行 / 前端 13.2k 行），但绝大多数能力停在「有入口、能跑一次」，没有一项到「别人抄要一年」。

## 一、先定标准：什么叫「独有且强」

一个能力只有同时过三关，才算资产：

1. **一句话能说清**：用户能复述（「它知道我耳机的曲线，所以每首歌都不一样」）。
2. **能被证明**：截图或当场 A/B 能听出差别；不是靠文案宣称。
3. **复制成本高**：竞品要拿到同样的数据/同样的推理链，而不只是照抄 UI。

按这个标准，把成熟度分五级：L0 没有 / L1 有入口 / L2 能用 / L3 可解释可复现 / L4 独有且被用户验证。

## 二、能力盘点（按证据，不按愿景）

| 能力 | 证据 | 级别 | 卡在哪 |
| --- | --- | --- | --- |
| 31 段 EQ + APO 参数导入 | `AudioMath.swift`、`EQMath.parse` | **L3** | 前级余量到 0.9.32 才按真实峰值算；没有人为「好不好听」背书 |
| 链路（ListeningChain）与按路由激活 | `Models.swift` `activeChain` | L2 | 只有「一条链路」，没有版本、没有对比、没有依据 |
| 每首歌的曲线记忆 | `SongCurve`、`SongCurveListView` | L2 | 有记忆、有依据字段，但没有「为什么是这条」的生成逻辑 |
| 一句话调音 | `SoundTuning`、`suggest_curve` | L2 | 一次改动而已，不留历史、不可比较、不解释推理 |
| 按住对比 | `beginCompare` / 桌面 B 键 | L2 | 只对比「适配 vs 平直」，不是「这首歌 vs 别的调法」 |
| 声音摘要 | `SoundSummary` | L2 | 只翻译当前曲线，不回答「它凭什么适合这首」 |
| 插件运行时（MusicFree） | `plugins.ts` + iOS 沙箱 | L2 | 能装能搜，播放链路刚通；无插件管理/更新/信任分级 |

| 有声书 / 新闻播报 / 语音合成 | `BooksView`、`Speech.py`? `SpeechRender` | L1 | 独立功能块，与主线无关 |

| 刷音乐（滑卡/抽卡） | `SwipePlayer`、`SwipeMode.vue` | L1 | 通用交互，放任何播放器都成立 |
| 测试与验证 | 9 个 TS 测试、37 个 Rust 测试文件、iOS 0 个可跑 XCTest | **L0.5** | 关键链路（沙箱、调音、刮削）没有运行时证据 |

## 三、残酷结论

1. **定位的三根柱子只有一根半是硬的**：EQ 引擎（硬）+ 每首歌记忆（半硬）；「为什么适合这首歌」和「agent 自动调」目前都只是细线。
2. **广度吃掉深度**：15 个能力块里 11 个是 L1–L2。每块都占着入口、文档和维护，没有一块能让用户说「离不开」。
3. **交互混乱的根因不是设计不好看，是没有唯一模型**：播放页、刷音乐、队列、歌词、曲线面板、调音面板各自为政，因为它们各自服务不同能力。

## 四、选三个「必须变强」的能力（其余冻结）

### A. 可解释适配（Explainable Fit）——把「每首歌的 EQ」做成真的

现在的曲线是「结果」，用户不知道它从哪来。要做到 L3/L4：

- 每条曲线必须带**三段依据**：耳机（测量或型号）、曲目特征（频谱/段落）、个人先验（校准或历史选择）。
- 依据必须**可复现**：同一首歌 + 同一副耳机 → 同一条曲线（随机性只允许出现在「多个候选」这一层）。
- 依据必须**可反驳**：界面上写明「这条依据来自 X；如果你换耳机，它会失效」。

验收：任选三首歌，能各用一句话说出「为什么这样调」，且换耳机后系统主动提示依据失效。

### B. 耳朵校准（Ear Calibration）——数据护城河

3–5 分钟的一轮 A/B 选择（低音多/少、人声前/后、齿音刺/钝），产出**个人听感先验**；之后每首歌的曲线都叠加这层先验。

- 别人能抄界面，抄不走你机器上这份先验；
- 它天然解释「每个人都能听到最适合的声音」这句话；
- 校准结果要能导出/备份（现有加密备份可承载）。

验收：同一首歌，校准前后各听一次，能听出「更像我想要的」；校准结果在重启后仍在。

### C. Agent 作为调音师（Agent Tuner）——把「自动」做成可审计的动作

现在只是「一句话改一次」。要做到：

- 每次改动留**历史**：谁提的、改了什么、为什么；
- **多候选**：同一句话给 2–3 条曲线，用户挑；
- **禁止越权**：模型只输出曲线与解释，不碰播放、不碰来源、不碰文件；
- **可回滚**：任意一次改动一键撤销，并保留审计。

验收：连续调三次，能回看每次的 diff 与理由，并能任选一次回滚。

### D（可选护城河）跨设备听感接力

把 `Handoff` 从「传文件」升级成「传听感」：iPhone 上校准的先验 + 这首歌的曲线，接到 Mac 上继续。已有雏形，成本低于重做一套。

## 五、明确冻结（保留可用，不再投入）

- 刷音乐 / 抽卡：留住入口，不再加交互创意。
- 歌词：有就显示，不做逐字动画、不做歌词海报。
- 有声书 / 新闻播报：与主线无关，冻结。
- 皮肤 / 玻璃：只在回归时修 bug。
- 插件市场式扩张：保留 MusicFree 兼容，不做插件商店。

冻结的意思是：**新需求进来先问「它让 A/B/C 更强吗」，不能就排队尾**。

## 六、交互收敛成一个模型：一首歌 = 一个声音档案

不管在哪个页面，面对一首歌只有四个动作：

| 动作 | 手势/入口 | 回答的问题 |
| --- | --- | --- |
| **听** | 播放 | 现在是什么声音 |
| **比** | 按住（iOS）/ 按住 B（桌面） | 没有适配是什么样 |
| **说** | 一句话 + 短语 | 我想让它变成什么样 |
| **查** | 点依据行 → 档案页 | 它凭什么这样、改过几次、能不能回滚 |

其余全部降级为二级：队列放播放页抽屉、歌词放封面翻面、插件/刮削放设置。**一个新交互只有在四个动作里找不到归属时才允许新增。**

## 七、路线图（每版一个可听验收）

| 版本 | 内容 | 验收（能听/能看） |
| --- | --- | --- |
| R1 | A 的骨架：曲线三段依据（耳机/曲目/先验）+ 失效提示 | 任选三首歌，各说清为什么这样调 |
| R2 | B 校准：3–5 分钟 A/B，产出先验并叠加 | 校准前后同曲对比，能听出差异 |
| R3 | C 审计：调音历史 + 多候选 + 回滚 | 连调三次可回看、可回滚 |
| R4 | D 接力（可选）：把先验与曲线跨端带走 | iPhone 校准，Mac 听到同样倾向 |

## 八、反方意见（先自己反驳一遍）

- 「依据」会不会变成一堆用户不看的字？→ 所以依据必须是一句话 + 一行来源，展开才看到细节；不写长文。
- 校准会不会让人觉得麻烦？→ 3–5 分钟、可跳过、跳过就用通用先验；校准结果随时可重做。
- 多候选会不会让选择困难？→ 默认给 1 条，主动点「再来一条」才给第 2/3 条。
- 冻结功能会不会让产品显得变窄？→ 变窄是目的：现在的问题是宽而浅。

## 九、判定这份规划是否成立

三个月后回看，如果用户能说出「它知道我的耳朵」而不是「它功能很多」，这份规划就成立；如果还是在比功能数量，说明执行又滑回了广度。

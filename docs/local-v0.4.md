# Awake

**让好音乐，越来越合拍。** macOS 本地音乐播放器，Rust + Tauri 2 + Vue 3。当前为 **v0.4.0 本地个性化重建版**。

这一版围绕“连接自己的曲库 → 开始聆听 → 收集真实反馈 → 改善下一次选曲”重建。云端 AI 与音乐生成按后续接入设计；目前不调用云端模型、不生成音频。

## 运行

要求 macOS 14+、Rust/Cargo、Node.js/npm；本地打包还需 Xcode Command Line Tools 和 Python 3。

```bash
npm ci --prefix ui
./Tools/build_rust_app.sh
open dist-rust/Awake.app
```

也可以单独运行前端：

```bash
npm run dev --prefix ui
```

浏览器访问 `http://127.0.0.1:1420`，可导入真实本地音频、播放、EQ、收藏和创建歌单。浏览器与桌面版使用不同的本地数据；浏览器音频仅保留在本次会话，偏好和歌单保存在当前来源的 localStorage 中。浏览器不读取桌面曲库，也不把浏览器输出包装成独占或原生采样率输出。

## 本轮为什么重建

源码审查发现的具体问题：

- **两条开发主线分裂**：Swift 版的远程曲库、歌词和自动 EQ 等能力没有完成 Rust 迁移，但旧说明把两版能力混写，难以判断当前版本实际能做什么。
- **界面先于闭环**：旧界面有固定示例歌词、硬编码 DemoMusic 路径、无法操作的上一首/下一首；没有听歌事件存储、偏好更新、推荐解释和歌单持久化。
- **播放状态不可靠**：原回调把播放游标按值捕获，外层结束判断看不到更新；旧线程和新线程共用停止标记，容易相互干扰；暂停实际是停止，继续会从头播放。
- **EQ 没有实时生效**：原实现播放前处理整曲；`set_eq_curve` 只校验并返回文本，播放中的音频没有更新。
- **验收缺少真实使用证据**：编译通过与静态截图不能证明播放、曲库、反馈学习和设备恢复有效。原解码测试还只在 DemoMusic 根目录找文件，实际示例在子目录中，因此可能直接跳过。

工程产物能证明这些缺口，不能证明某个开发工具本身造成了这些问题。重建重点是统一产品主线和验收标准。

## 个性化如何工作

`awake-core/src/taste.rs` 是可解释的本地排序器，不是大模型。它用实际音频播放帧统计收听时长，跳转距离不计入收听。

- 完整收听，或达到歌曲时长一半（最高 120 秒）的收听，增加对应艺人和风格的偏好权重。
- 收藏直接增加曲目、艺人和风格的相关权重。
- 主动切走且实际听了不足 30 秒的曲目，降低推荐分数。
- 曲名、艺人、专辑和风格标签参与描述匹配。“专注”额外匹配 ambient / instrumental 等现有标签；它不能在标签缺失时理解音频情绪。
- “探索”优先未有效收听的曲目；这不会自动发现外部歌曲。
- 智能歌单保存来源条件，来源重新扫描后按当前曲库重新计算。

最近 5,000 条收听事件保存在桌面本地档案。当前没有跨设备同步、用户画像 embedding、跨时段习惯或长期反馈效果实验。

## 音频实现与边界

```text
文件 → 解码到内存 → 必要时 sinc 重采样 → 每帧 EQ → 平滑音量 → cpal → 当前默认设备
```

本轮修复了会话取消与真实游标，EQ 在输出回调中应用；回调使用预先分配的帧缓冲，更新曲线时尝试读取共享状态。平直 EQ 直接绕过滤波。重采样尾部显式 flush，输出长度按比例精确确定。设备 F32、I16、U16 格式均有分支，其余格式会返回错误。

这仍不是已经完成的发烧级音频引擎：整曲解码/重采样会增加长音轨的启动时间和内存占用；流式 ring buffer、预解码下一首、真正无缝、独占模式、测量耳机校正、热切换消音和平滑滤波器系数还需要继续完成。设备默认输出变化每五秒检查一次；恢复已保存的听感，正在播放时重开设备并恢复位置，期间会有短暂中断。

界面只显示实际文件参数和已协商的输出采样率，不声称已实现 bit-perfect、原生 DSD 或主观音质提升。

## 接入 AI 的边界

`ui/src/agent.ts` 提供 `MusicAIProvider` 接口：

- `curate` 接收有限候选曲库和精简偏好，返回候选 ID 与推荐理由。
- `resolveProposal` 去掉曲库外 ID 和重复 ID，避免模型编出不存在的可播放歌曲。
- `generate` / `getGeneration` 表达排队、运行、成功、失败的音频生成任务；生成请求显式包含用户发起标记。
- 当前只启用 `curateLocally`；没有注册云端 provider、没有 API 密钥入口、没有音乐生成调用。创作简报不是生成作品。

后续云端 provider 必须在桌面后端或受控服务中保管凭据，并在实现后添加对应契约与失败路径测试。

## 后续开发顺序和验收

1. **可靠的长时间聆听**：将整曲内存处理替换成后台流式解码和有界缓冲，预载下一首；以长音轨启动耗时、稳定内存、零掉音、无缝样本连续性验收。
2. **设备与声音**：用稳定设备 ID 代替名称，提供测量来源明确的耳机校正；分别验收设备切换、响度匹配 A/B、EQ 响应与峰值安全，不以“支持 96 kHz”代替听感测试。
3. **订阅内容闭环**：先做 RSS 抓取、解析、失败重试与目录曲目匹配，再接 WebDAV / Plex。订阅条目、匹配到的曲目与实际播放资源分开建模；显示匹配率、可播放率和最近刷新状态。当前版本没有 RSS 订阅。
4. **AI 策展**：先用真实听歌档案、受限候选与来源目录接入一个 provider；测量推荐接受率、早跳过率、重复率和探索覆盖率，失败时明确回退本地。
5. **AI 原创作品**：接入实际音乐生成服务，做任务状态、试听、版本、导入曲库和作品来源记录；以能生成、能试听、能保存并可再次播放的真实音频验收。

## 代码与数据

```text
ui/src/
  App.vue / styles.css       产品页面与视觉
  useAwake.ts                播放队列、状态同步、推荐和设备偏好
  bridge.ts                  Tauri 命令与真实音频浏览器适配
  agent.ts                   本地选曲入口与未来 AI provider 合约
  TrackList.vue / Artwork.vue 共享曲目与媒体组件
rust/crates/awake-app/src/
  lib.rs                     Tauri 命令与扫描/分析后台任务
  playback.rs                音频会话、游标、暂停、跳转、实时 EQ
  experience.rs              偏好/歌单/设备听感原子持久化
rust/crates/awake-core/src/
  taste.rs                   偏好排序与反馈
  lyrics.rs                  LRC 解析
  decode.rs / eq.rs / resample.rs / library.rs / …
```

桌面数据目录：`~/Library/Application Support/com.seven.awake/`。

- `library.json`：曲库；`artwork/`：封面。
- `taste.json`：收听事件、收藏、歌单、设备曲线与创作简报；先写临时文件再原子替换，保存失败不提交内存更新。
- 损坏的听歌档案会先复制为 `taste-corrupt-<timestamp>.json`，再初始化空档案。
- Swift 版使用独立的旧数据目录，当前没有自动迁移。

## 验证

```bash
npm run build --prefix ui
cargo test --manifest-path rust/Cargo.toml -p awake-core -p awake-app --lib

# 真实输出回归：使用实际 CoreAudio 设备，音量为零；需 DemoMusic
cargo test --manifest-path rust/Cargo.toml -p awake-app --lib real_output_pause_seek_eq_and_eof -- --ignored --nocapture
```

2026-11-11 本轮结果：30 项普通测试通过；单独执行的 1 项真实 CoreAudio 静音回归通过；前端类型检查与生产构建通过，macOS 本地应用完成签名校验。

普通测试包含 EQ、采样率转换、曲库、标签、听歌反馈、来源过滤、LRC 和播放会话状态。演示音频相关旧测试在 DemoMusic 不存在时仍会提前返回，不能把这种通过视为真实音频验收；本轮在可用 DemoMusic 下运行，并修复了解码测试的递归查找。

浏览器交互回归使用真实 FLAC：导入、播放/暂停保持位置、收藏改变排序、描述匹配、动态歌单保存、EQ 预设与设备记忆、简报保存、⌘K 搜索。视觉检查覆盖桌面和小屏布局。声卡静音回归只能证明软件控制与输出路径，不等于 DAC 回环测量或主观听感评测。

旧版功能和发布说明保存在 [v0.3 历史说明](docs/legacy-v0.3.md)，其中的功能表不能作为当前版本能力清单。Swift 源码保留作功能迁移参考，后续主线为 Rust + Vue。

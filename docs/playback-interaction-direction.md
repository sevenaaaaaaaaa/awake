# 播放交互：按定位重做（v2）

> 这份取代 `playback-interaction-review.md` 里「P0 手势收敛 / P1 队列 / P2 歌词」那套排期。
> 那套是通用音乐播放器的功能清单，和本产品的定位没有因果关系。

## 定位（用户原话，作为验收标准）

- 把耳朵唤醒。
- 每个人都能听到最适合的声音。
- 最符合这首歌的 EQ。
- 深度整合 agent，能自动帮他调整所有配置。

判据：一个交互如果换到任何播放器上照样成立，它就不是这里的差异化交互。

## 旧方案错在哪

| 旧提案 | 为什么不算数 |
| --- | --- |
| 手势收敛（vertical / cards 一套语义） | 只是把两套手势合并，仍然在解决「换歌」，与「声音」无关 |
| 队列抽屉 | 通用播放器标配；没有它显得缺，有了也不构成价值 |
| 歌词视图 | 同上，且与「这首歌应该怎么响」没有关系 |
| 皮肤细节 / 触觉分级 | 打磨，不是方向 |

结论：这些可以有，但都排在「声音」后面，不能占主手势、不能进首屏。

## 由此推出的四条交互（按重要性）

### 1. 这首歌的声音摘要（播放页第一块）

进来先回答一个问题：**这首歌现在为什么这样响**。

- 一句话结论：「60–200 Hz +3 dB 让鼓更近；4 kHz −1 dB 压住齿音」。
- 一行依据：来自你的耳机测量 / 你的偏好先验 / 这首歌的频谱特征；没有依据就写「没有依据，当前是手动曲线」。
- 开关：跟随这首歌 / 锁定当前曲线。

数据都已经在手边：`PlayerInstrument.swift` 的路由与曲线、`ListeningChain`、预设。缺的是「一句话解释」这一层。

### 2. 按住 = 对比「适配 vs 未适配」（核心手势）

- 按住封面（或曲线区）= 听「没有为这首歌调过」的声音；松手回到适配后。
- 这不是普通的 EQ 旁路：对比的是**这首歌的适配曲线**，旁路只是它的一个特例（曲线为零时）。
- 桌面已有 `ui/src/bypassKey.ts` 的按 B 旁路，把它升级成同语义；iOS 还没有，需要新增。
- 理由：调音唯一能验收的方式就是当场 A/B，别的一概是猜。

### 3. 一句话调音（agent 的主入口）

- 播放页给几个短语：`人声太靠后` / `低频糊` / `想更亮` / `太吵`，外加一句自由输入。
- agent 直接改当前曲线，并把改动回显成可读的差异：「3 kHz +2.0 dB、8 kHz +1.0 dB」，带「撤销」。
- 这是「深度整合 agent，自动调整所有配置」落在播放页的那一面：用户说人话，agent 动曲线。
- 现有 `AISettingsView` 只有服务配置；缺的是播放页里这条回路。

### 4. 自动适配的可见与可控

- 切歌时自动套用这首歌的曲线，用一句话 + 一次微动效说明「已为这首歌匹配」。
- 可以「锁定当前曲线」「关闭自动」，默认开。
- 前提：需要「每首歌 → 曲线」的映射；当前只有链路级预设与手动曲线。这是最大的工程量，也是定位的核心，值得先做数据层。

## 保留但不作为卖点

队列、歌词、迷你条、刷音乐：该有就有，按最低成本维持，不再往上面加交互创意。

## 切片

| 片 | 内容 | 依赖 | 粗估 |
| --- | --- | --- | --- |
| V1 | 声音摘要（只读）：一句话 + 依据 + 跟随/锁定开关 | 现有路由/曲线/预设 | 1 天 |
| V2 | 按住对比（iOS），与桌面 B 键同语义 | 曲线写入通道 | 0.5 天 |
| V3 | 一句话调音：短语 → agent → 改曲线 → 回显 → 撤销 | AI 服务配置 + 曲线写入 | 1.5 天 |
| V4 | 自动适配：每首歌映射 + 切歌套用 + 关闭/锁定 | 数据层 | 2 天 |

验收口径：每条都要能在真机上听到差别；「编译通过」不算。

# Awake 0.9.0

macOS 14+，Apple Silicon 构建（ad-hoc 签名），首次打开可能需要在「隐私与安全性」中允许。这一轮补齐接力的反方向：电脑 → 手机。

## 本次重点

- **接力可以双向了**。手机 → 电脑（0.7.1 起）保持不变，新增电脑 → 手机：底部播放条「数据与接力」里多出「这台电脑接力到手机」，搜索同一 Wi-Fi 上前台开着「接收接力」的手机，输入手机显示的 6 位配对码即可交接当前曲目与进度。
- **发现与识别**：电脑端只列出手机接收端（Bonjour 实例名前缀 `AwakePhone-` 或 TXT `to=phone`），不会把另一台电脑当目标；电脑自己作为接收端时也在 TXT 里标注 `to=desktop`、`v=2`，旧版手机端仍能照旧找到它。
- **只发元数据**：请求体仍只有曲名 / 艺人 / 专辑 / 时长与进度，不含音频、文件路径、账号、密码或设备标识；配对码不落盘，不重试。
- **界面兜底**：搜不到手机时可手动选择地址，失败原因直接给中文（配对码不对、手机曲库没有这首歌、连不上、尝试过多）。

## 协议

两个方向共用一套载荷、配对码与匹配规则，见 [接力协议 v2](../handoff-protocol.md)。`to` 缺失按电脑处理，因此只升级一端也能继续用原有方向。

## 验证

- Rust：`cargo test -p awake-app -p awake-core` — awake-app 81 通过 / 10 按需忽略 / 0 失败，awake-core 42 通过；新增 8 项接力发送测试，其中 1 项真起本地 HTTP 假手机做端到端（校验请求路径 `/handoff`、请求体字段与响应翻译）。详见[验证记录](../validation-v0.9.0.log)。
- 前端：`npm run build --prefix ui` 通过 `vue-tsc` 类型检查。
- 构建：`Tools/build_rust_app.sh` 产出 `dist-rust/Awake.app`，`codesign --verify --deep --strict` 通过，`open` 启动后写入 `frontend_ready version=0.9.0`。
- 未验证：真实 iPhone 与这台 Mac 之间的实际交接（需要实机同一 Wi-Fi 操作），以及 Intel 切片（本轮只构建 arm64）。

## 与 iOS 的配合

iOS 0.9.0 同时提供「接收接力」。两端都升级后双向都可用；这是本轮唯一需要两端一起升级才能用上的方向。

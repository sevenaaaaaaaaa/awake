# Awake 0.9.9

macOS 14+（仅 Apple Silicon，ad-hoc 签名）。这一版只加一个交互：**在「正在播放」页按住 B，整条 EQ 临时旁路；松手写回原曲线。** iOS 端本轮没有改动，仍是 0.9.8 的 IPA。

## 为什么是「按住」而不是一个开关

调音的时候，人要的不是「关掉 EQ 再打开」，而是**一边听一边比**：低频多的那 3 dB 到底帮了忙还是糊了人声，只有切过去的瞬间才听得出来。开关要点两次、眼睛要离开曲线、耳朵要等下一次呼吸；按住是零次点击、零等待、零记忆负担——手指抬起来，原曲线就回来了。

## 做了什么

- **按住 B = 旁路**。按下瞬间把当前 31 段增益快照下来，把全零曲线真写给后端（`set_eq_curve`），输出走平直；松手把快照写回。不是视觉切换，是把旁路后的曲线真的送到音频链路。
- **只在「正在播放」页生效**，且当前曲线非平直时才响应——平直曲线没有可旁路的东西，此时按 B 不写后端、界面也不闪。
- **按住期间界面说清楚状态**：链路条 EQ 段写「旁路」、输出段写「旁路直通」，曲线上方一枚「旁路中 · 松手恢复」，下方一行说明「整条曲线压平后直接送输出，松手写回原曲线」。松手后恢复原样。
- **不给旁的按键添麻烦**：不认 ⌘B / ⌃B / ⌥B；输入框、文本域、下拉与 `contenteditable` 里敲 b 是在打字，不触发；长按产生的重复事件不算新的一次按下（否则快照被覆盖，松手回不到原曲线）。
- **两次 IPC 串行**：按下与松手各一次 `set_eq_curve`，快按快放时后发的「原始曲线」可能先到，最终停在平直曲线上而没有任何报错。现在两次调用挂在同一条 promise 链上，顺序有保证。
- **切走应用自动恢复**：窗口失焦时收不到 keyup，旁路会一直挂着；`blur` 与离开「正在播放」页都会写回原曲线。

## 实现

- `ui/src/bypassKey.ts`：按键判定、输入控件判定、平直判定、旁路曲线构造，四个纯函数。
- `ui/src/bypassKey.test.ts`：6 项（修饰键、长按 repeat、输入控件、平直曲线、不可变快照、非法长度）。
- `ui/src/App.vue`：状态、两次 applyEq 的串行链、keydown/keyup/blur 接线、离开页面时收尾。
- `ui/src/StageInstrument.vue`：旁路态在链路条、曲线标题与状态行的呈现。

## 验证

- 前端测试 `npm test --prefix ui`：**51 通过 / 0 失败**（0.9.8 是 45 项）。
- 前端构建 `npm run build --prefix ui`：通过（`vue-tsc --noEmit` + vite build）。
- 桌面包：`Tools/build_rust_app.sh`（arm64），`codesign --verify --deep --strict` 通过。

**没有做到的**：本机没有屏幕录制权限，`screencapture` 报 `could not create image from display`，所以这一版同样没有截图证据。旁路的听觉效果只能由你按住 B 自己判断——这也正是这个功能唯一能算数的验收方式。

## 仍未闭合

- 拖动进度条时不显示这一段音频的波形，松手才跳（盲拖）。
- 曲库/队列不能拖拽排序：后端没有「不打断播放地重排队列」的命令，前端只持有一份快照，重排必须连带重发 `play_queue`，会打断当前播放。
- 曲线只能涂改，还不能存成预设。
- iOS XCTest 在本机仍跑不起来（模拟器 service hub 起不来），验收口径仍是「编译通过 + 独立 harness」。

## 安装

解压 `Awake-0.9.9-macos-arm64.zip`，把 `Awake.app` 拖进「应用程序」。ad-hoc 签名，首次打开需在「系统设置 → 隐私与安全性」里允许。

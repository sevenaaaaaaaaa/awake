# Awake 0.9.39

macOS 14+（仅 Apple Silicon，ad-hoc 签名）。这一版补上一个存在了很久的缺口：**桌面也开始按歌记曲线**，
并且把两端的纯逻辑第一次放进了可运行的自检里。iOS 本轮只做规则收拢，仍是同一套听感判定。

## 为什么是这一版

R1–R4 把「依据 → 先验 → 自动调 → 跨端带走」这条链铺完了，但桌面只接过了先验：iOS 导出的档案里明明有
N 首按歌曲线，桌面侧根本没有落点——`songCurves` 在 Rust 里不存在。所以「同一副耳朵」在桌面上只成立一半。

另一半是验收。四个版本的结论基本停在「ARCHIVE SUCCEEDED + 包内字符串对上了」，这种验收有个致命问题：
把常量改坏，它照样是绿的。这一版顺手把纯逻辑钉进了自检。

## 做了什么

**按歌记忆（桌面）**

- 新增 `song_curves.json`：桌面 track id → 曲线 + 三段依据，外加一份先验。原子写，坏文件留副本再空库起步。
- `import_listening_profile`：解析 iOS 档案，按曲名落到本地曲目；**不再把先验直接加到当前曲线上**。
  导入只落库，生效发生在切歌时——所以连点两次导入不会叠两次，这一点是结构上不可能，而不是靠弹窗提醒。
- `curve_for_track`：切歌时先问「这首歌有没有记忆」。有就用记忆（叠好先验、限幅 ±12），没有就回落链路曲线。
- 两端的歌 id 不通用（iOS 是 UUID，桌面是曲库 id），唯一能对上的是档案里的 `titles`。同名多首时**不猜**。

**依据与未匹配（桌面）**

- 「声音」页新增「这首歌的依据」：耳机 / 曲目 / 先验三段逐条写出，缺哪段写「未记录」。
- 依据失效时说清「记的是哪副、现在用的是哪副」，并给「用当前曲线更新记忆」。
- 导入时落不下来的曲线保留为待指定清单，候选可点：精确同名在前，「夜航」↔「夜航 (Live)」这类包含关系接在后。
  一条近似都没有时明说「先在桌面导入这首歌」，不假装有候选。

**设备内自检**

- 桌面 `self_check` 返回 9 条：先验叠加与限幅、关掉先验、没有先验、档案解析、未知版本拒绝、
  同名多首不猜、依据失效判定、失效文案、曲目指纹。
- 每条断言里的期望值都是写死的字面量，不再调一次生产函数算期望——否则改坏常量后两边一起变，永远绿。
- 界面在「声音」页底部，顶部写明「全绿不等于产品可用」。

**规则收拢（iOS）**

- `EarRules`：`applyingPrior` / `basisMismatch` / `basisHint` 抽成纯函数，`MobileStore` 只做转发。
- `CurveBasis.fingerprint` 独立出来，与桌面 `listening::track_fingerprint` 同一写法。
  **一处行为修正**：以前再由头为空时，曲目依据会留下一个悬空的「 · 」，现在空的那段直接不写。

## 实现

| 文件 | 作用 |
| --- | --- |
| `rust/crates/awake-core/src/listening.rs` | 档案解析、段数校验、曲名归一化匹配、先验叠加、指纹与依据判定（两端共用规则） |
| `rust/crates/awake-app/src/song_curves.rs` | `song_curves.json` 落库、导入、按曲查询、记住/忘掉、待指定清单 |
| `rust/crates/awake-app/src/self_check.rs` | 9 条纯逻辑断言 |
| `ui/src/CurveBasisCard.vue` | 三段依据卡片与待指定清单 |
| `ui/src/SelfCheckCard.vue` | 自检清单 |
| `ui/src/curve.ts` | 曲线解析的前端类型（字段跟随 Rust 的 snake_case） |
| `ios/Awake/Models.swift` | `EarRules`、`CurveBasis.fingerprint`、两个方法改为转发 |

## 验证

- Rust：`cargo test -p awake-core -p awake-app --lib` → **core 57 / app 123，0 失败**（10 项 ignored 是需要真实音频的既有用例）。
- 前端：`npm test --prefix ui` → **57 通过 / 0 失败**；`vue-tsc --noEmit` exit=0。
- 打包：`npm run build --prefix ui` → exit=0（349 KB JS）。
- 自检的「能红」验证：把 `MAX_GAIN_DB` 从 12 改成 6，`prior.clamp` 立刻变红并写出
  「期望 12，实际 6」，其余 8 条不受影响；改回 12 后 9/9 全绿。
- iOS：`xcodegen generate` + `xcodebuild ... build` → **BUILD SUCCEEDED**。

## 已知边界

- **GUI 的点击路径没有手点过**：导入档案 → 切歌这一串在真机上还没走一遍。逻辑、类型、打包都验了，
  但「手点一遍」不在这一轮的能力里，所以这里不写「已验收」。
- 先验目前只叠加到「这首歌的记忆曲线」上，不叠链路曲线——桌面运行态的曲线就是用户此刻听到的一切，
  再叠一次会重复。要让先验作用于所有歌，得先把「链路基线」独立出来，那是 S3 的正题。
- 加密备份只搬 `library.json` 与 `taste.json`，`song_curves.json` 不在里面：换机恢复后按歌记忆会消失。
- iOS 自检页尚未落地（规则已抽出、构建通过），提示词见 `docs/prompt-s2-ios-selfcheck.md`。

## 升级

- 从 0.9.38 直接覆盖安装，无需迁移。首次运行会创建空的 `song_curves.json`。
- iOS 若已升级到 0.9.39：已有的按歌曲线与先验照常读取；依据文案里以前以「 · 」结尾的曲目段，
  下次「记住这首歌」时会写成不带尾巴的形式。判定规则未变。

# 0.9.48

> 版本号 0.9.48（桌面与 iOS 同一号），iOS build 60。
> 落实「两个界面、各自成套」：传统界面原样保留；耳形长出自己的**声音层**——
> 调音不再需要跳进传统页，预设、这首歌的记忆、精确微调都在耳朵旁边完成。

## 背景

0.9.47 之后你反馈：主页（耳形）不错，但从耳形进到设置/声音类页面后，满眼还是老的交互界面，
恍惚且割裂。结论：**传统界面保留不动；新界面自成一套。** 这一版先把最常用的那条线补齐——
「调整声音」不再把人送回声音实验室，而是打开耳形自己的声音层。

## 声音层（耳形右侧滑出）

- **输出**：当前耳机与曲线来源（这首歌有记忆 / 链路曲线），带失效提示；
- **预设**：平直 / 温暖 / 人声 / 柔和，点了曲线当场变、耳形同步变形；
- **这首歌**：记住这首歌 / 忘掉这条——每首歌的记忆不用再去声音实验室翻；
- **精确**：31 段逐条 ±0.5 dB 微调（耳形上的拖动负责粗调，这里负责对数值）；
- **出口**：传统界面 ⌘L——两个世界的边界从此是明示的。

## 入口

- 耳形右上角「声音」按钮；
- ⌘K 里的「调整声音」在耳形状态下打开的也是这一层（传统状态下仍是声音实验室）。

## 验证

- 真实浏览器点击回归（playwright-core + Chrome for Testing）四套脚本全过：
  - 声音层 6 项：按钮开层、预设改变曲线（色带 0 → 11429）、记住有回应、
    微调生效（读数 +2.0 → +2.5 dB @20 Hz）、⌘K 入口、传统界面出口；
  - 键盘 12 项、比全通路、说两轮照旧全过（无回归）；
- 前端 85 通过 / 0 失败，`vue-tsc --noEmit` 与生产构建通过；
- cargo `awake-core` + `awake-app` `--lib` 全部通过；
- 桌面 0.9.48 构建安装 `/Applications`，进程存活；iOS 仅版本同步（模拟器编译随打包验证）。

## 未验证

- 真机手感：声音层滑出的动画、开着层同时拖耳形的组合操作；
- 皮肤（黑白以外）下声音层的观感。

## 你能看到的

**「音乐来源」页多了电台台站列表。**

搜一个词（`jazz`、`BBC`、`古典`），拿到一份公开台站列表。每台后面跟着一句结论：
"未探测（声明 MP3，解码器支持）"、"可播（探测为 aac）"、"opus 需要打开「用 ffmpeg 兜底」"。

- 结论只有一套：能不能放由 Rust 判，界面不自己再判一遍；
- 点「探测」是真连上去解 4 秒，报编码与采样率，结论存 7 天；
- 探测失败**不写缓存**——"这次没探成"和"这个编码不行"是两件事，混在一起会挡住能播的台；
- 编码明确解不了的台（今天只有 Opus）不会进列表，省得点了没声音。

**MusicBee 导入现在能处理跨盘的库。**

以前只能填一个「Windows 根」，库里跨 `F:\Music` 与 `G:\Archive` 时有一半路径落不上。
现在会先告诉你这份库跨了几个盘根、各多少条，每个根一个挂载点。

命令行也一样，`--map` 可以给多次：

```sh
awake-cli mbl inspect MusicBeeLibrary.mbl \
  --map "F:\Music=/Volumes/F" --map "G:\Archive=/Volumes/G"
```

**古典专架认得出更多写法了。** Handel 的 `HWV`、Beethoven 的 `WoO`、Liszt 的 `S.`
这三种作品号之前完全不认；`D 899`（不带点）也被漏掉；中文库的「贝多芬：第五交响曲」
因为用的是全角冒号，之前也解析不到。这一版都补上了。

## 命令行（开发与验证用）

```sh
awake-cli mbl tags <MusicBeeLibrary.mbl> [--tag 65=TrackTitle ...]
awake-cli classical-check <library.json|数据目录>
```

- `mbl tags`：列出这份库真实出现过的 tag 码、对应的名字、条数、三个样例值。
  这是验证码表的唯一手段——样例值语义对不上名字，就是码表错了。表外的码会显式打
  `unknown(code=N)`。
- `classical-check`：在你自己的曲库上量古典命中率，并列出解析不到的十条样例，
  照着真实写法补规则。

## 还没做的（不假装）

- **真实 `.mbl` 仍然没有。** 码表来自官方 SDK 枚举，属高置信推断；只被合成样本验证过
  "命令能跑、字段能读出来"。给我一个文件，`mbl tags` 一条命令就能定论。
- **真实古典库仍是 0。** 本机曲库 18 首、古典专架 0 首，所以真实命中率**无定义**（分母为 0）。
  语料上的 31/31 只说明"语料覆盖的写法都处理了"，语料和规则同源。
- **`album_artist` 是指挥时仍会被当成作曲家**（`Herbert von Karajan` 这条已知缺口）。
  要修得再补一张指挥家/乐团表。
- **电台还不能在应用内播放。** 电台不是曲目，播放队列只吃库内曲目；要播得在播放内核
  加一条"从任意 reader 播"的路径。界面上写清了，没有假装能播。
- **hover / focus / active / disabled 四态和触屏真机没验。** headless 截图拍不到这些。

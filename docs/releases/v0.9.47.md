# 0.9.47

> 版本号 0.9.47（桌面与 iOS 同一号），iOS build 59。
> 修 0.9.46 耳形的「点不动」：三处真实缺陷 + 一处交互补全。起因是你装上 0.9.46 后反馈
> 「整体效果不错，不过所有地方都点不动」——本轮全部定位并修复，且每一处都有真实浏览器
> 点击复现与修复后的回归脚本（`/tmp/awake-e2e/`，playwright-core + Chrome for Testing）。

## 上一版错在哪（三处真实缺陷）

1. **睡着时整屏无响应。** 代码里睡着分支是「什么都不做」；刚启动时队列为空、连轨道节点
   都没有，于是没有任何鼠标入口。现在：**点一下耳朵 = 打开 ⌘K 找一首**，这就是
   「放一首，唤醒它」的入口本身。
2. **「说」的输入框一直是隐形的。** 输入框写在 `<svg>` 里——SVG 命名空间里的 HTML 控件
   不渲染（0×0、position 失效）。同一批遭殃的还有：**投票药丸和「说」菜单的文字完全
   不可见**（四个词全是黑块）、轨道节点的标题与依据副标题、刻度字号——因为这些元素是
   `createElementNS` 动态创建的，身上没有 Vue scoped 的 data-v 属性，scoped 样式一条
   都套不上。现在：输入框挪出 SVG；动态元素的样式挪进以 `.ear-svg` 限定作用域的
   非 scoped 块；截图确认文字全部可见。
3. **点完一首歌回不到耳朵。** 点曲目后焦点落在「播放」按钮上，键盘规则「焦点在按钮上
   就不理单字母键」把 E 挡掉了。现在 E/L 的判断提前，文本框里打字仍然不触发。

## 顺手补上的

- **轻点耳朵 = 播放/暂停**（按住仍是听原样、拖动仍是捏，互不冲突）；
- 按住/拖动只在耳朵本体上生效，屏幕角落误触不再让整条曲线旁路；
- 曲线是平直时按住，不再静默——直接告诉你「这条曲线是平直的，先在声音里调一条，或让搭子来」；
- 「说」的每种结局都有回应：预览环境明说要在桌面应用用；没配 AI 服务转达后端原话
  （「请先在设置里配置 AI 模型」）；调音中会提示等待；
- ⌘K / 存歌单 / 来源表单 / toast 层提到根层级——耳形全屏时它们不再因为不渲染而失灵。

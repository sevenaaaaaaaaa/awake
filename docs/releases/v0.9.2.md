# Awake 0.9.2

桌面端与 iOS 同步发版。iOS 是**未签名 IPA**，需要自行重签。

## 这一版修了什么

### 一、iOS 一开 App 就弹 `OSStatus error -50`

症状：手机上每次打开 App 都弹一句

```
Awake
The operation couldn't be completed. (OSStatus error -50.)
知道了
```

成因：那句英文是 `player.error` 把 `NSError.localizedDescription` 原样交给界面的结果。
冷启动时全 App 只有一条路径会抛 CoreAudio 的 OSStatus——`MobilePlayer.init()` 里的
`configureSession()`，而它是被 `AwakeApp.init()` 触发的，那时 UIApplication 还没启动完，
`AVAudioSession.setCategory` 拿不到一个可用的会话。其余所有错误落点写的都是中文，
所以这句英文不可能是它们发的。

改法：

- 构造 `MobilePlayer` 不再碰 `AVAudioSession`；改由 `RootView.task` 调 `prepareSession()`
  在界面起来之后配置。真正的 `setActive` 仍然只在播放时发生。
- 新增 `AudioFailure.describe(_:action:)`：CoreAudio / AVFoundation 的错误统一翻成中文并保留
  OSStatus 码值，业务错误（`AppFailure`）与未知域的原描述都不吞。
- 四个 error 落点（播放 / 恢复播放 / 调整音效 / 会话激活）全部改用它。
- 原始错误写进 `os.Logger(subsystem: com.seven.awake.ios, category: audio)`。

现在同样的失败会显示成：

```
播放失败：系统音频通道没准备好或被其他应用占用，先退出正在播放的应用再试（OSStatus -50）
```

**验证到哪一步**（不打折）：

- `xcodebuild build` → **BUILD SUCCEEDED**；
- 用真实 `AudioMath.swift` 编译的 harness → ALL GREEN（7 项，含 -50 的翻译与码值保留）；
- 修后模拟器冷启动：首页正常、不弹窗、不崩；
- **没有在真机上复现那个 -50**，也没有在真机上确认修好了——干净模拟器本来就不弹；
- `AwakeTests` 里同款断言已写入，但模拟器 test host 卡住，**未跑通**。

### 二、版本号守卫扩到四个落点

0.9.1 发版时 `tauri.conf.json` 还停在 0.9.0：`Tools/build_rust_app.sh` 自己生成 Info.plist 所以已发的包没受影响，
但 `npm run tauri build` 读它，按那条路构建会打出写着 0.9.0 的 0.9.1 包。
现在 `version.test.ts` 同时钉住 `ui/package.json`、`version.ts`、`rust/Cargo.toml` 的 workspace 版本、
`tauri.conf.json`；`ios/project.yml` 故意不纳入（iOS 与桌面可以各自版本）。

## 升级

- macOS：替换 `Awake.app` 即可，曲库与设置都在原地。
- iOS：未签名 IPA 需要用你自己的证书重签后安装；重签后钥匙串里的 Token 需要重新填一次（换签名会换掉钥匙串访问组）。

## 仍然开着

1. 真机上的 -50 没有复现路径。如果 0.9.2 之后还弹，请截一句新的提示文字——现在它会带上动作名与码值。
2. `AwakeTests` 这条测试通道要在能跑通的环境里补一次红→绿。

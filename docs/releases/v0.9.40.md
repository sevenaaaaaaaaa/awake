# Awake 0.9.40

macOS 14+（仅 Apple Silicon，ad-hoc 签名）。这一版只修一件事：**本地导入不再复制自己**。

## 为什么是这一版

用户在「添加音乐 → 导入「文件」里的 Awake 文件夹」之后，曲库里出现大量 UUID 标题、
「未知艺人」的曲目，旧的与新的同时存在；每点一次导入数量继续涨，界面越来越卡。

定位到的不是「忘了写判重」，而是判重的三个前提同时不成立：

1. **扫描会吃到自己的缓存（主因）**。导入会把文件复制进 `Documents/Awake/Music/<UUID>.<ext>`，
   而用户能选的正好是 `Documents/Awake` 这一层。选择器那条导入路径没有任何「这是我自己写的目录」
   判断，于是第 2 次扫描把上一次写出的副本当新文件，再复制一代——标题就是副本文件名。
2. **身份是绝对路径**。App 数据容器带 UUID，重装 / 恢复备份后会变；选择器还可能返回
   `/private/var/...` 而内部拿的是 `/var/...`。同一个文件换了个绝对路径，在曲库里就是「新歌」。
3. **旧曲目没有身份**。0.9.5 之前没有 locator 字段，老曲目 locator 是空串，任何重扫都命中不了；
   同内容换名 / 换目录也认不出。

## 做了什么

**扫描：托管目录整棵跳过**

- `LibraryImport.audioFiles(in:limit:excludingManagedFrom:)` 跳过 `Music` / `Artwork` / `Speech` / `News`，
  遇到目录直接 `skipDescendants()`；两条导入入口（选择器、兜底文件夹）传同一个 root。
- 判定同时看标准化绝对前缀与「Documents 之后」的相对路径，兜住 `/var` 与 `/private/var` 两种写法。

**身份：容器内记相对路径**

- `LibraryImport.locator(for:documents:)`：容器内文件记 `own:Awake/2.Blue Bird.mp3`，容器外仍是绝对路径。
- `identityKey`：比较时把旧档案里的任意容器绝对路径折成同一形式；CUE 分轨的 `#cue-N` 后缀原样保留。

**判重：路径之外再按内容**

- 路径没命中时，用「字节数 + 时长（0.1 秒）+ 文件头 64 KB 的 FNV-1a 哈希」再判一次；
  命中就沿用已有曲目，只把 locator 更新成新地址。尺寸 + 时长只是便宜的预筛，真正决定合并的是文件头哈希。
- 自己生成的音频（语音合成 / AI 作曲 / 内置示例）带 `cache:<file>` 身份，不再因为 locator 为空被误判。

**整理：已经长出来的重复**

- `MobileStore.repairLocalLibrary()`：启动时自动跑一次（`libraryRepair.v2`），设置 →「曲库维护」可手动再跑。
- 每组保留「标题像人写的 > 被歌单/听书/评分引用过 > 有艺人/封面/歌词 > 更早导入」的那条；
  收藏、封面、歌词、评论、人工元数据从被合并项补过去；歌单、听书进度、听歌历史、评分、调音记录、
  每首歌的曲线、创作任务里的曲目 id 一起改指。
- 只删除「合并后已无曲目引用」的缓存文件；另清 `Music/` 里超过 1 小时没人引用的孤儿文件。
- 改动前备份 `library.json.before-repair-<时间戳>`，只保留最近三份；写盘失败整批回滚。
- UUID 标题若能用导入时记下的 `originalFilename` 还原，就还原成人能读的标题。

**性能**

- 一次导入只 `save()` 一次、只赋值 `state.songs` 一次；判重用字典索引，不再每首扫全库。

## 实现

| 文件 | 作用 |

| `ios/Awake/LibraryImport.swift` | 托管目录排除、`own:` 身份、内容指纹、去重分组与保留规则、文件头哈希 |
| `ios/Awake/Models.swift` | `importFiles` 索引判重 + 内容二次判重 + 一次落盘；`repairLocalLibrary`；两条导入入口共用排除规则 |
| `ios/Awake/AwakeApp.swift` | 启动跑一次整理 |

| `Tools/library_import_harness/`、`Tools/run_library_import_harness.sh` | 真实源码 + 26 项断言的纯逻辑 harness |
| `docs/local-import-dedupe.md` | 根因链、判重规则、验证命令、未验证项 |

## 验证

- 纯逻辑：`bash Tools/run_library_import_harness.sh` → **26 项断言 / 0 失败**。含「反复扫描候选不增长」
  与旧行为复现（不排除托管目录时副本确实被当成新文件）。
- iOS 编译：`xcodegen generate` + `xcodebuild ... build-for-testing` → **TEST BUILD SUCCEEDED**（含 4 条新用例）。
- `swiftc -typecheck`（iPhoneSimulator SDK 27.0，`arm64-apple-ios17.0-simulator`）→ **0 error**。
- 回归基线：`cargo test -p awake-core -p awake-app --lib` **57 / 0 失败**；`npm test --prefix ui` **57 / 0 失败**。
- **XCTest 没有在本机跑起来**：这台机器没有 `Simulator.app`，`test-without-building` 停在起 test host、
  日志 0 增长，已按 PID 终止。4 条新用例需在真机或装了完整 Xcode 的机器上补跑。

## 已知边界

- 同一段音频在曲库里存在两份（例如同一首歌收在两个专辑），整理会合并成一条。这是这次选择的取舍：
  重复导入造成的损失远大于「合法的同内容双份」。
- 只处理本地曲目（`sourceID == nil`）；远程来源的重复成员仍由各自的扫描合并。
- 桌面端不复制文件进被扫描目录，本次未改。

## 升级

- 覆盖安装即可，无需迁移。首次启动会自动整理一次：
  合并重复、歌单 / 听书进度 / 评分改指到保留项、清理多余缓存，并留下 `library.json.before-repair-<时间戳>`。
- 整理完成后，再点「导入 Awake 文件夹」只会看到你真正放进去的文件。
- 想手动再跑一次：设置 →「曲库维护」→「整理曲库（合并重复、清理缓存）」。

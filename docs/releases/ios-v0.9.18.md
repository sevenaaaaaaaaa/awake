# Awake iOS 0.9.18

iOS 17+。这一版把桌面端的「网络音乐插件（枪弹分离 JS）」搬到 iOS：**插件是弹药、播放器是枪**。
以前手机上只有 WebDAV / Plex / Telegram 三种来源，现在可以装自己的 MusicFree 兼容插件。

## 之前的问题

- **手机上装不了插件**：桌面 0.9.5 起就有「网络音乐插件」来源，iOS 一直没有，两边曲库因此不一样宽。
- **想测插件只能开电脑**：手机上没有入口，也没有供插件跑的 JS 环境。

## 现在（四步，0.9.15 → 0.9.18）

- **插件库（0.9.15）**：设置里新增「网络音乐插件」。导入 `.js`（≤512 KB、最多 64 个、只收 UTF-8 文本），存在 `Documents/plugins/`，同名覆盖，左滑删除。
- **插件源（0.9.16）**：贴 `myPlugins.json` 地址就能列出插件并一键装；也可以把 json 放进「来源配置文件夹」，点「从配置文件夹读」。注册表规则与桌面同一套（数组 / `plugins` / `data` / `list`，按地址去重，上限 200 条）。
- **沙箱（0.9.17）**：插件跑在一个不可见的 WKWebView 里，用的是桌面那 890 行沙箱的**同一份编译产物**（`ui/src/plugins.ts` → 27.5 KB IIFE）。插件的 `fetch` 由 App 代发（`awakeHttp` 消息桥 → URLSession），所以没有 CORS 问题；只放 http/https，请求体 ≤2 MB、响应 ≤8 MB、超时 15 s。
- **播放（0.9.18）**：点插件歌曲时调 `getMediaSource` 解析出地址与请求头，带上头上限下载，先落 `.part`、`AVAudioFile` 验证能解码，再改名进曲库，然后走现有 EQ 链路。

## 怎么用

1. 设置 →「网络音乐插件」→ 插件库（N）→ 导入 `.js`，或贴注册表地址点「安装」。
2. 点某个插件进去 → 输入歌名搜索 → 点「入库」。
3. 回曲库点那首歌：第一次播放会解析并下载，之后就是本地文件。

## 验证

- 四个版本都走 `Tools/build_ios_app.sh` 的 Release archive，全部 `ARCHIVE SUCCEEDED`。
- IPA 体积：0.9.15 → 1,722,303 字节；0.9.16 → 1,738,783；0.9.17 → 1,772,433；0.9.18 → 1,777,098。四份连同同名 `.sha256` 都在 iCloud Drive；0.9.18 的 sha256 是 `c1f2dc3fd2825cf09ff6e96dfd2acd24c0273a6a1bb49aaaedc8400d935c2562`。
- 包内核对：`Payload/Awake.app/pluginSandbox.js` 存在（`getMediaSource` 4 处）；二进制里有 `awakeHttp`、`这个插件没有实现 getMediaSource，无法播放`、`插件给出的播放地址不是 http(s)`、`音频解码为空` 等新文案。

**没有做到的**：本机模拟器 service hub 起不来，这一整条链路（WKWebView 注入、消息桥、`callAsyncJavaScript`、带头下载、解码）**没有任何运行时证据**。验收只能由你在真机上点一遍；插件抛的原文会显示在搜索页，不会静默。

## 仍未闭合

- **插件歌曲没有「来源」卡片**：曲库里能看到、能播，但设置页找不到对应来源，也不能「刷新来源」。
- **删插件不清曲目**：只删 `.js`，它入库的歌还在，点了会报「插件文件不见了，请重新导入」。
- **队列不预解析**：`recommendations()` 只收已有本地文件的曲目，所以插件歌要一首一首点。
- **无扩展名的流地址会被拦下**：解码校验宁可报错不静默；m3u8 分片不支持，只按整文件下载。
- **插件依赖面**：需要额外 `Referer` / `User-Agent` 才放行的源、或依赖沙箱没垫的 `require`，第一次跑大概率会报错——把那句原文给出来就能定位。

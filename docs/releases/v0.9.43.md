# 0.9.43

> 版本号 0.9.43（桌面与 iOS 同一号），iOS build 55。
> 这一版把"接来源、探测编码、兜底解码"这条线补完，并把首页那条降权规则真正接上数据。

## 你能看到的

**「音乐来源」页多了两块。**

- **MusicBee 曲库**：选 `MusicBeeLibrary.mbl` → 先给你一组数字（解析多少条、曲库多少首、对得上多少、会改变多少、对不上多少）→ 确认后才写入。只读那个文件、不写回；写之前自动备份曲库；播放次数只增不减，重复点也安全。
- **电台解码 · 用 ffmpeg 兜底**：默认关。因为兜底要装 ffmpeg、首播还要多等一会儿，所以做成开关；打开后界面会告诉你 ffmpeg 在哪，没装就直接说 `brew install ffmpeg`。关着的时候遇到 Opus 台，会明确说"需要打开兜底"，而不是干等一个没声音的播放按钮。

**画布首页的降权规则真的会生效了。** 之前 `composeHome` 里写着"连续 3 天没点过的 tile 自动降权"，但一直没人给它喂数据；现在会记下每块最后一次点击时间（存本地），满 3 天自动让位，钉住的可以抵消。点过的记录读坏了也不影响首页——当作没点过。

**首页不再假装有电台。** 没有电台来源时，电台那块不会被算出来再藏起来；它就是不出现。

## 命令行（开发与验证用）

```sh
awake-cli radio probe   <url> [秒数] [--ffmpeg] [--codec opus] [--cache 目录] [--uuid 台站id]
awake-cli radio verdict <url> --cache 目录 [--uuid 台站id] [--ffmpeg]
awake-cli mbl inspect|apply ...
```

- `radio probe`：真实解码一段直播流。直接解不了时会说清"加 `--ffmpeg` 能兜底"还是"本机还没装 ffmpeg"。
- `radio verdict`：只查缓存，多给一行「计划」——直接播放 / 走 ffmpeg 兜底 / 放不了（附原因）。
- 台站缓存 7 天过期；探测失败**不写缓存**，不会把"猜的结论"存下来。

## 这一版修掉的旧账

| 旧问题 | 处理 |
| --- | --- |
| 首页"继续听"用 `as unknown` 去猜播放进度字段 | 直接用 `useAwake` 暴露的 `playback.position` |
| 降权规则有代码没数据（`idleDays` 从没传过） | 新增本地记录，规则真正生效（5 条测试） |
| 电台"能不能放"的判定有两套（Verdict 与 plan） | 合成一套：探测只管"是什么编码"，`plan` 只管"怎么放"；开关改了不用重探 |
| `decode.rs` 头部注释说有个 `fallback` 模块，实际不存在 | 改成事实：Rust 只做识别，转码在 Swift `TranscodeService`；直播另有 `stream::decode_via_ffmpeg` |
| `Bucket::unheard()` 死代码 | 删除，测试改为直接断言 `total - heard` |

## 还没做的

- 电台还没有列表界面（缓存与判定都在，只缺一个台站列表页）。
- MusicBee 的 tag 码到字段名的映射仍缺真实 `.mbl` 样本，所以只导入播放次数/上次播放/入库时间，不导入标题与艺人。
- 跨多块 Windows 盘的 `.mbl` 仍只映射一块（`win_root` 只有一个）。
- 视觉验收（375/768/1280 截图）这一版没有做；新加的两块面板只验到"能编译、能构建、类型通过"。

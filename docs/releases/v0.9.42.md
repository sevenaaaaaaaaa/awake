# 0.9.42

> 版本号 0.9.42（桌面与 iOS 同一号）。iOS build 54。
> 这一版的重心：**把"库变大以后"的四个页面接上**，并给 MusicBee 曲库与公开电台把路铺到能跑。

## 你能看到的

**首页多了一块「今日版面」。** 它不是编辑排的，是按你的库状态算出来的：继续听、有几首等你听一下、今天这一首、专架、电台、校准。每块下面都写一句"为什么在这里"。原来的 hero 与情绪卡仍在下面，随时可以删。

**新增三个页面**（左侧导航最后三项）：

| 页面 | 它回答什么 |
| --- | --- |
| 专架 | 古典 / 轻音乐 / 现场各有多少首、凭什么进来的 |
| 适配报告 | 新入库里还有多少首没有曲线、分成几批、被什么卡住 |
| 艺人画像 | 每个艺人：播了几次、完成率、跳过率、常在几点 |

**古典专架可以按作品浏览**：一行是「作曲家 · 作品 · 作品号 · N 段」，点一条播这首作品的第一个乐章。作曲家与作品号是从标签里解析出来的，**没有写进曲库数据**——解析错了改代码就行，不用迁移数据。

**适配报告不会骗你**：它不显示"已自动适配 380 首"这种数字，因为这一版还没跑批量分析。它只报欠账：多少首没有曲线、分几批、是不是缺参照物（耳机档案或校准）。

**iOS**：上一轮遗留的界面改动随本版入库——「添加音乐」失败时不再被全局提示吞掉、调音与声音页整理、UITest 补充。功能面与 0.9.41 一致。

## 命令行（不影响界面，给开发与验证用）

```sh
awake-cli mbl inspect <MusicBeeLibrary.mbl> --root 'F:\Music' --mount /Volumes/Music
awake-cli mbl apply  <MusicBeeLibrary.mbl> --library <数据目录> --root 'F:\Music' --mount /Volumes/Music --dry-run
awake-cli radio probe https://example.com/live.mp3 4
```

- `mbl apply` **只读 .mbl、不写回**；播放次数只增不减，入库时间只在库里为空时补；写库前自动备份到 `backups/musicbee-<时间戳>/`；同一份 `.mbl` 第二次跑会直接报"未变化，跳过"。
- `radio probe` 真实解码一段直播流并报编码/采样率/电平。实测：mp3 与 ADTS AAC 各解出 4.02 秒，OGG 台里其实是 FLAC 也能解；**Opus 解不了**——symphonia 0.5.5 没有 opus 解码器，实测报 `unsupported codec`，所以 Opus 台暂不列出。

## 还没做的

- 电台与 MusicBee 都还没有界面：能跑的是命令行与底层解析。
- 首页「继续听」依赖播放进度暴露；如果播放器不提供位置，这一块不会出现（不会报错）。
- 电台尚未接进「音乐来源」，所以首页电台块暂时不出现。
- 批量分析（真正跑一遍频谱再决定曲线）没有接；适配报告只报欠账。

# Awake 0.9.4

macOS 14+，本轮构建**仅 Apple Silicon（arm64）**，ad-hoc 签名，首次打开可能需要在「隐私与安全性」中允许。这一轮只修一件事的两个面：**刷新能不能信**——桌面端手动刷新不再把过期扫描结果写回曲库，iOS 端 Plex 扫描不再把不完整或空的结果当成完整结果。

## 这次修正

- **桌面：过期扫描结果不再写回**。手动刷新是「先取来源、异步扫描、再提交」，中间可能过去几十秒。以前提交时直接按扫描开始前的来源对象 `save`：来源在这期间被移除，来源会被插回来；来源的地址、账号或分区被改动，旧结果会把新配置盖掉。现在提交前比对来源是否仍存在、且 `id`/`name`/`kind`/`url`/`username`/`password_key`/`trust_self_signed`/`section`/`files`/`last_scan` 都没变；不一致就返回错误并保留当前状态，不会再出现「刷新成功，但曲库变成扫描之前的样子」。
- **桌面：刷新不再清空收听痕迹**。以前一次扫描会整批替换该来源的曲目，收藏、播放次数、上次播放时间、加入时间全被新记录盖掉。现在按曲目标识合并：已有曲目继承这四项，新曲目才用扫描值。`library.json` 写入失败会整体回滚内存快照，不再出现「内存里是新的、磁盘上还是旧的」。
- **iOS：Plex 扫描不再接受不完整结果**。分页到 20000 首上限时，以前直接停下并返回已经拿到的部分；`totalSize` 显示还有更多、或者根本没有 `totalSize` 可核对时，现在按失败处理。响应不是可识别的 Plex 音乐目录、所有分区合计没有曲目，也按失败处理——失败走「保留原曲库」路径，不会因为一次合法空结果把来源的旧曲目删光。
- **iOS：同一个文件/文件夹重复导入不再生成副本**。以前每次导入都会复制一份新缓存、生成新的 Song ID。现在用标准化路径（`standardizedFileURL.resolvingSymlinksInPath().path`）做稳定身份：重复导入同一文件直接跳过；重新导入文件夹时按各文件的稳定路径去重，新文件追加，本次扫描中消失的文件从该文件夹的曲目集合里移除。文件夹成员关系写进 `library.json` 的 `importedFolderPaths`，不持久化系统文件夹安全作用域 URL。
- **iOS：远程来源可以移除了**。以前只能加不能删。现在每个 WebDAV / Plex / Telegram 来源都有「移除来源」（二次确认），一起清掉：来源记录、所属曲目、歌单里的引用、听书记录、听书进度、`source.<id>` 钥匙串凭据、按 Song ID 命名的 Awake 缓存音频。手动导入的本地曲目不受影响。整个过程先把缓存文件移进暂存目录再提交持久化，任一步失败就整批回滚——内存曲库、缓存文件、钥匙串凭据都回到移除前。

## 数据与兼容

- `library.json` 新增可选字段 `importedFolderPaths`（iOS 侧写入）。旧曲库没有这个字段也能直接读，缺失时按空处理。
- 桌面端 `snapshot.sources` / `tracks` 结构未变；旧曲库、收藏、播放记录直接可用。
- 已连接的来源不需要重连、不需要重新授权。

## 未验证

- **iOS XCTest 未执行**。本机 Xcode-beta（27A5228h）里没有 Simulator.app，`xcodebuild test` 与 `test-without-building` 都卡在起 test host：`DTServiceHubClient failed to bless service hub for simulator`，无 `.xcresult`。能证明的只有：`build-for-testing` = `** TEST BUILD SUCCEEDED **`（测试代码可编译），以及把 `PlexScanValidation` / `LibraryImportIdentity` 的真实源码行机械抽出、用 `swiftc` 独立编译跑出 **12 项断言 / 0 失败**。**这不等于 XCTest 通过**，需要在装了完整 Xcode 的机器或真机上补跑。
- 真实 Plex 账号的一次完整授权与扫描没有跑（需要账号与服务器）；本轮两条 Plex 修复的依据是单元测试与逻辑 harness。
- 真机重签安装与来源移除交互没有跑（需要开发者证书与真机）。

# Awake iOS 0.9.7

iOS 17+。这一版只处理一件事：**Plex 连上了、曲目也识别出来了，但曲库里看不到**。

这是个老问题。0.9.5 修的是「空分区 / 空分页把整次扫描杀掉」，可修完之后依然有人反馈「加了 Plex，任何地方都看不到」。这一版把根因找到了：**问题不在扫描，在入库之后没有任何入口。**

## 1. 根因：曲目进来了，但没有地方让人看见

- 桌面端连接成功会调 `focusSource()`，把曲库筛到刚连上的来源；
- iPhone 端连接成功只有一句 `dismiss()`，曲目被 `append` 到 `state.songs` 末尾；
- 而 iOS 曲库是一个**平铺列表：没有来源筛选、没有按来源分组、没有「刚添加」视图**。

于是来源卡片写着「PLEX · N 首」，人在曲库里却找不到——曲库越满，新加的越沉在底部。看起来就是「加了但任何地方都看不到」。

## 2. 改了三处

- **曲库新增来源筛选条**：`全部来源 · N 首` / `<来源名> · N 首`，选谁看谁。每个来源后面直接跟着它自己的曲目数，「到底进没进来」一眼可答。
- **连接成功后自动切到「曲库」**，并把筛选设到刚连上的那个来源，与桌面端 `focusSource()` 行为对齐。
- **连接成功后明确提示**：「「<来源名>」已加入 N 首，正在为你显示这个来源。」不再静默关表单。

## 3. 补上了这条链的自动化验证

以前所有 Plex 修复都只在手写的响应片段上验证，「连接 → 扫描 → 入库 → 列表可见」在真机和模拟器上从来没跑过。现在仓库里有两个可重复的东西：

- `Tools/fake_plex_server.py`：说 Plex 官方 XML 协议的本地假服务器（`/library/sections`、`type=10` 分页、`Media/Part/@key`、专辑封面），每个请求都写日志；
- `Tools/e2e_ios_plex_visibility.sh`：起假服务器 → 构建 → 装进模拟器 → 让应用自己走一遍扫描入库 → 读诊断日志与落盘 `library.json`，断言曲目数与来源对得上。

实跑结果（2026-11-19，Xcode 27.0 / iPhone 17 Pro 模拟器 / iOS 27.0）：

```
E2E 扫描成功 songs=3 入库后曲目总数=3
落盘：来源 1 个（plex 1），曲目 3 首，其中该来源 3 首
PASS: Plex 连接 → 扫描 → 入库 全链路通过（3 首，来源与曲目都对得上）
```

完整输出见 `docs/validation-ios-plex-visibility.log`。

## 4. 仍未闭合

- **真实 Plex 账号端到端**：假服务器覆盖的是协议形态，不覆盖你服务器上的分区类型、共享权限、超大曲库上限。需要你的地址与 Token 才能把这一段也钉住。
- **模拟器 XCTest runner**：本机 `xcodebuild test` 停在 24 KB 的 `.xcresult` 不再前进（UI 与单元测试都一样），所以本次验证走应用内 e2e 通道，`AwakeUITests` 里的用例仍需在能起 runner 的机器上补跑。

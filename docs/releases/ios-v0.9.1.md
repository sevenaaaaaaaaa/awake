# Awake iOS 0.9.1（未发布）

> **状态：这个版本没有发过包，也没有 tag。GitHub 上不存在 `ios-v0.9.1`。**
>
> 它原本只打算做一件事：把 iOS 的版本号从 0.9.0 对齐到 0.9.1，功能零改动。
> 这件事最后没有发生——音频会话的修复跟着 **0.9.2** 一起发了，见 [v0.9.2](v0.9.2.md)。
> 这份文件保留下来，是为了让人看到「曾经打算发、最后没发」，而不是假装它存在过。

## 当时打算做什么

- iOS 侧源码不动，只把 `MARKETING_VERSION` 从 0.9.0 改成 0.9.1，让两端「关于」页版本一致；
- 顺带记录：0.9.1 的桌面改动（Plex 来源类型、深夜档本地时区、音乐生成预置下拉）全在 Rust 与 Vue 里，iOS 不涉及。

## 实际发生了什么

| 时间线 | 事实 |
| --- | --- |
| `3e17dec` | 只改了 `ios/project.yml` 的版本号与这份说明，没有构建、没有发包 |
| `831e2ab` | 音频会话修复（不再在 `App.init` 里碰 `AVAudioSession`）才落地，**晚于**那次版本号对齐 |
| `e5625b7` | 版本号整体前进到 0.9.2，iOS 与桌面一起 |
| `ios-v0.9.2` | iOS 上**第一个**真正带这个修复的包 |

所以早先这份说明里「0.9.1 的 iOS 包含音频修复」这句话，在提交顺序上站不住：修复合进来的时候，0.9.1 的版本号已经不再指向最新代码了。写在这里，是因为这种「文档跑在发布前面」的错，比没写更危险。

## 如果以后真要补一个 0.9.1

技术上可行：`16ce072` 那个提交的 iOS 版本号仍是 0.9.1，且已经包含音频修复，从那里跑 `Tools/build_ios_app.sh` 就能出一个能装、能跑的 0.9.1 包。

但不建议这么做：

- 0.9.2 已经带着同样的修复发了，补发 0.9.1 只会让不知情的人装到**更旧**的版本；
- 版本号并不能靠补发变回历史——装过 0.9.2 的机器再装 0.9.1，系统会当成降级；
- 真正需要修的口径问题（文档声称发布了、实际没发布）已经由这份文件说清楚，不需要再挂一个 release 来证明。

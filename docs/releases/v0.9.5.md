# Awake 0.9.5

macOS 14+，本轮构建仅 Apple Silicon（arm64），ad-hoc 签名，首次打开可能需要在「隐私与安全性」中允许。这一轮只做三件事：把「本地文件导入」和「Plex 曲库显示」两个反复出现的基础问题落到根因上，并把「枪弹分离」网络音乐插件作为一类来源接进来。

## 这次修正

### 本地文件导入：两个根因

- **符号链接不再被静默跳过**。扫描用 `DirEntry::file_type()` 判断条目类型，而它来自 lstat、不跟随符号链接。macOS 上把「音乐」软链到外置盘是最常见的用法，旧代码会把整棵链接树当成「不是目录也不是文件」，于是探测与扫描都是 0 首。现在改用 `metadata()`（stat）判断类型，并带已访问目录集合与 32 层深度上限，链接环不会卡死扫描。
- **一个坏子目录不再拖垮整次导入**。旧代码遇到任何一层 `read_dir` 失败（权限、损坏挂载点）就整体报错，哪怕探测已经数到文件，「选了文件夹却导不进来」就是这么来的。现在只有**根目录**读不了才报错；深层子目录失败记录后跳过，其余文件照常导入。

### Plex 曲库显示：与 iOS 0.9.4 同一条规则

- **空音乐库 / 空分页不再报「格式无效」**。`MediaContainer` 不带 `Metadata` 是空页的正常形态（空分区、翻页到底）；只有 `size` 与 `totalSize` 都缺失才按服务器返回垃圾处理。
- **零首结果按失败处理**。一个可识别的 Plex 音乐目录里合计 0 首时，扫描返回失败而不是成功空结果 —— 失败走「保留原曲库」路径，手动刷新不会再把来源上次的曲目清空。
- **专辑封面**。扫描时按 `parentThumb → thumb → grandparentThumb` 收集专辑图，一张专辑只抓一次，按内容魔数落盘到封面目录并回填曲目；已有缓存文件时不再重复下载。专辑视图不再是清一色占位图。

### 新增来源类型：网络音乐插件（枪弹分离 JS）

- **兼容 MusicFree 风格插件**：一个独立 `.js` 导出 `platform` / `search` / `getMediaSource`（以及可选的 `getLyric` 等）。来源类型里选「网络音乐插件（枪弹分离 JS）」→ 选插件文件 → 添加来源；来源卡片上的「搜索并入库」打开搜索面板，挑歌入库。
- **入库与播放分离**：入库只保存曲目信息（locator 保存原始 musicItem，按平台 id 去重）；播放前由插件 `getMediaSource` 解析出直连地址与请求头，随 `play_track.resolved` 交给现有 HTTP Range 播放管线（同源重定向最多 3 跳、地址必须是 http(s)）。
- **插件沙箱**：`fetch` 走后端受限通道（绕过 WebView 的 CORS；地址/方法/头/体与响应体都有上限，Host / Content-Length / Proxy-Authorization 不允许注入），并自带 `CryptoJS` 子集：MD5 / SHA1 / SHA256 / HmacMD5 / HmacSHA1 / HmacSHA256 + Utf8 / Latin1 / Base64 / Hex 编码，签名类插件不用再装依赖；`require("crypto-js")` 兼容旧写法。
- **插件来源不参与周期刷新**：它们按搜索入库，没有目录可扫描；移除来源时插件文件一起删除。打开自动更新的旧逻辑对这类来源不生效。

## 数据与兼容

- `library.json` 结构未变；`kind` 新增取值 `plugin`，旧曲库照常读取。
- 已连接的本地 / Plex / WebDAV / Telegram 来源不需要重连。
- 插件来源没有服务端凭据；`url` 是 `plugin://<来源 id>`，插件文件在数据目录 `plugins/<id>.js`。

## 验证（2026-11-18 本机实跑）

- Rust：`cargo test -p awake-app --lib` — **116 通过 / 0 失败 / 10 按需忽略**；`cargo test -p awake-core -p awake-cli` — **44 通过 / 0 失败**。新增：符号链接目录遍历、坏子目录不拖垮导入、Plex 空分区 / 零首拒收 / 封面缓存、插件导入幂等与更新、去重与清洗、HTTP 入参校验。
- 前端：`npm test --prefix ui` — **34 通过 / 0 失败**。新增 `plugins.test.ts`：MD5 / SHA1 / SHA256 已知向量、HMAC 与 Node crypto 全长度对照、Base64 往返、搜索结果与解析结果的规范化、插件走宿主通道的 fetch 契约。
- 类型与构建：`npx vue-tsc --noEmit` 无输出；`npm run build --prefix ui` 通过。
- 应用构建：`AWAKE_ARCHS=arm64 bash Tools/build_rust_app.sh`，产物与校验值见下方「已发布产物」。

## 未验证

- **真实 MusicFree 插件与真实 Plex 服务器的端到端没有跑**（需要用户自己的插件文件与账号）。插件沙箱验证的是契约（搜索结果形状、解析结果形状、签名）、Plex 验证的是协议夹具；真机行为需要在装了插件的桌面上补验。
- **插件播放的真实音频没有跑**。解析出的地址交给的是既有 HTTP Range 管线（该管线有独立的 Range/seek 测试），但插件返回的 CDN 地址是否支持 Range 取决于目标站点。
- **AES 解密、FormData 请求体、`require()` 非 crypto-js 模块不在沙箱内**：依赖这些的插件会在对应调用点得到一句明确的中文错误，而不是静默失败。
